- **A task commit under a slow `pre-commit` hook now runs under a time limit the caller carries, and a hook that overruns it is stopped whole.** `git commit` used to share the one fixed limit of every git read and was killed alone: the hook it had started kept running, and a git killed uncatchably left `.git/index.lock` behind. The commit now runs in a process group of its own under `commit-task-work.py --commit-timeout SECONDS` (or the built-in limit when none is given), and an overrun kills the whole group. The refusal then says what state the repository is in: HEAD unmoved with the index put back, or HEAD already moved because a hook after the commit was what ran long (the commit exists and the index is left alone), and an `index.lock` still present is named by its path and not removed.
