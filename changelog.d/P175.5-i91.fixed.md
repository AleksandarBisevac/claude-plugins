- **A red run's step times are read against the run that timed each step itself, `meta.ado.stateMap.task` accepts `held`, and `hold` refuses a blocked task.** A repeated run copies a step from an earlier one with no time of its own, so after a green run, a repeated green run and a red one the step-time reading used to find nothing to compare and say `no-basis`; each step is now read against the newest earlier run of the same subject that timed that step, and the reading's basis names the run per step. The slow-step line rounds its ratio up to one decimal, so a step named for taking more than twice its last time no longer prints `2.0x`. The plan schema's task `stateMap` took no `held` key although the reference says it may name one; it now does, on the task side only. `/audit:task hold` on a blocked task is refused, naming `unblock`: it used to overwrite the block's reason, and `release` then returned the task to `pending` with the block cleared and no `unblock` on record.
