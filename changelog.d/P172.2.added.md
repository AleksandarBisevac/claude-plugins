- **A project can declare a fast pre-gate, and the writer is told to pass it before returning.** `meta.buildCommands.preGate` is one command - several joined with `&&`, as the map's other entries are - that tells a writer in seconds whether its change is broken at all. The writer's prompt lists it ahead of the gate's own list, and the executor's brief carries it as a `Pre-gate` section (under `executor.runsGate: never` the section says the executor runs no gate, the pre-gate included, rather than listing it as a check to report). The command is spelled through `meta.nodePreamble` as a gate entry is. A `preGate` that cannot be run - blank, not a string, or a `review-only:` read - is said so in one sentence instead of reading as none declared, and a plan that declares none gets both briefs byte for byte as before. It is an ordinary `buildCommands` entry, so the plan schema, `/audit:task build-command` and the validator already carry it; a near-miss spelling (`pregate`, `pre-gate`) is an ordinary entry, and `executor.preGate` in the config is still reported as an unknown key. A plan that already uses the name `preGate` for a command of its own will see that command listed as a pre-gate.
