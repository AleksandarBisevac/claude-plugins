- **Starting a task settles only that task's stale gate.** `audit-task.py settle` takes `--task ID`: it narrows that one task's stored wide gate and writes only the shard of the phase the task sits in, leaving every other phase's stale gate, the phase and bug values and the stale index stubs to the call over the whole plan. The drive's settle before a start now passes it, so driving one phase no longer rewrites a sibling phase's shard in its own tree with a did-line that names only the task being started; and a settle that exits 0 while the task's gate did not move is reported as the gate not moving, not as a settle from a gate to itself.
