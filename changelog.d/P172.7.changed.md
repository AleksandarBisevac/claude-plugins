- **A task gate's affected selection is computed once per tree identity, so a second ask over the same tree no longer pays for it again.** `run-test-gate.py` keeps the answer of the selection (which suites a task's change can break) under a key made of the tree's content identity - the one the gate's own reuse identity is taken over, with the recorder's own writes left out - the paths the selection was asked about (which a task's declared files decide), the plan's meta (`meta.phaseGate` among it), the names of the task's own gate entries, and the bytes of the modules that make the selection. A later ask over the same key reads the kept answer and runs none of the project's listings; a change to any of those asks again, a write the recorder itself makes between two asks does not, and an answer measured while the tree moved is not kept. The answer lives in `<git common dir>/audit-selection`, outside the tree it judges, so keeping one moves neither the tree's identity nor what `git status` reports, and the newest few are kept. Nothing is kept for a caller that names no project and no plan, and a kept answer that cannot be read is a selection measured as before.
