- **A writer's red-first proof makes two runs, not three, when its task gate ran the proof's own tests and reported how many cases it ran.** On the writer path the drive asks the helper for `red --fix-by-gate` and files that proof over the green recorded task-gate run that stands for the fix run, binding that run's id to the block (`redFirst.fixLegRunId`). A run stands for it when it holds a step of the proof's own command that ran in that run rather than being reused from an earlier one, exited 0, had no suites muted, and reported at least as many cases as the proof's task run collected, and when its coverage named each test file the proof was made over. Which runners report a count decides which gates can bind: pytest, jest, vitest, mocha and Playwright through their own summary lines, and the selftest sweep through the totals it prints, where each file the proof's task run graded red needs a count of its own from the sweep's per-file lines. A house suite run directly, and unittest, report no count the gate reads, so they do not bind. Any other run has the helper make the fix run after all, and that proof is filed instead; when that fix run cannot prove, for example because it timed out, the return is filed as `could-not-prove` with the reason. A bound proof's basis says what the gate run showed, and it carries no implementation digest from a round that no fix run read. A change to a declared implementation file alone no longer re-proves a proof whose fix run is the gate's. `submit` (the executor path) keeps the fix run. The helper sizes its deadline, and judges whether the runs fit it, for the two runs `--fix-by-gate` makes rather than three.
