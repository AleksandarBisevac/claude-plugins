- **A writer's red-first proof makes two runs, not three, when its gate ran the test.** On the writer path the drive asks the helper for `red --fix-by-gate` and files that proof only over the green recorded task-gate run whose coverage named each test file the proof was made over, binding that run's id to the block (`redFirst.fixLegRunId`). A run that did not name them, was not green or recorded no coverage has the helper make the fix run after all, and that proof is filed instead. A change to a declared implementation file alone no longer re-proves a proof whose fix run is the gate's. `submit` (the executor path) keeps the fix run. The helper sizes its deadline, and judges whether the runs fit it, for the two runs `--fix-by-gate` makes rather than three.
