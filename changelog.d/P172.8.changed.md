- **A task's re-gate after a red runs that red's suites first, and a red there stops it.** When the task's previous recorded run was red, the next measured run of its gate takes each red step's failing suites ahead of the gate, narrowed the way a base run narrows them. If they come back red, the gate's own steps are not started: each is recorded by name as not run, and the run is red on those suites alone - so a fix that did not fix costs the suites that were red, not the whole gate. If they come back green, the whole gate runs, measured rather than repeated in part, and the verdict, the counts and the declared gate the commit binds are the gate's own. A red step that can only run whole, or whose runner named no suite, runs in its place in the gate, and the run says so. The drive's sentence for a red answered by a kept base now names the per-suite base runs that measured it instead of a run id nobody recorded.
