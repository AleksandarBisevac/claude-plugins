- **A task's re-gate runs last round's red suites beside the gate only where the two cannot share state.** The red-first stage ran beside the gate's steps in the same working tree on every re-gate, so a gate step that keeps the stage's suites - the bare spelling, or a path list holding only them - ran the same suite twice at once, and any runner keeping state in the tree (a test database, a coverage file, a fixed port, a cache directory) could collide with itself and fail the gate on a spurious red. The stage now runs beside the gate only when no remaining gate step keeps its suites and the red run recorded the selftest sweep's own summary for them - read off the evidence ledger, not off the command's path - since the sweep runs each suite in scratch directories of its own; everywhere else it runs ahead of the gate as it did before, and a red there starts none of the gate's steps. `run-test-gate.py` prints which of the two it chose and why. The limit is documented: another runner printing the sweep's summary line would be trusted to isolate its children too.
