- **A red-first leg whose exact inputs did not change is replayed, not run again.** `stamp-verification.py red` keeps each finished leg under a key over HEAD, the command, the leg, the bytes of the files laid over HEAD, stubs, overlays, the dependency plan, its own code, the interpreter and the environment - in `audit-red-legs` under git's common directory, newest entries only, and only when the inputs read after the leg equal those read before it. A hit replays the leg's code and text and says so in the payload's `legs` (`reused`, `key`, `recordedAt`, zero seconds); the throwaway tree is built only when a leg misses, so a re-proof after an edit that did not touch a leg's inputs - the baseline above all - costs nothing for that leg.
