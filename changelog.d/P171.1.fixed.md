- **The drive no longer charges a task with a red that its own record writes caused.** The base run, the time record and the start the drive writes into the plan sit uncommitted in the tree a task gate reads, so a project check that reads the plan could go red on them alone; the red was then read against a base that did not hold those writes and charged to the task, which blocked it for a human. A base run (`run-test-gate.py --base-of`) now lays the recorder's own paths (the plan, its shards, the journal and the filed returns) over its tree from the tree the red ran in (`--recorder-from`, the project when not given), and still reads as its commit's clean tree, its dirty basis counting those writes. A recorder path the red's task declares in its own `files` is not laid: an edit the task made there is its work, so that path keeps the base commit's content - and a recorder write inside it is then read as the task's. Only a base that carried the writes the red's tree held can charge a suite to the task: one measured for that red, or any base when the red's tree held no recorder write, which the run's record now keeps. Against any other base, a suite it would charge to the task reads not comparable (`not-knowable`), the reading keeps which suites that rule moved, a kept base answers no such red, and the drive measures the base for that red - and only for that one: a `not-knowable` of any other cause is not measured again. A red the recorder's writes alone cause then reads as red at base too (`gate-red-base`). A red the task's work causes beside it is still the task's when it fails a case the recorder's writes leave passing; one failing the same case is read as red at base, since the reading compares failing cases and that case fails at base too. The cost is one more base measurement for each red that a kept base would have charged to the task.
