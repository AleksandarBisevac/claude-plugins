- **The drive no longer charges a task with a red that its own record writes caused.** The base run, the time record and the start the drive writes into the plan sit uncommitted in the tree a task gate reads, so a project check that reads the plan could go red on them alone; the red was then read against a base that did not hold those writes and charged to the task, which blocked it for a human. A base run (`run-test-gate.py --base-of`) now lays the recorder's own paths (the plan, its shards, the journal and the filed returns) over its tree from the tree the red ran in (`--recorder-from`, the project when not given), and still reads as its commit's clean tree, its dirty basis counting those writes. Only a base that carried the writes the red's tree held can charge a suite to the task: one measured for that red, or any base when the red's tree held no recorder write. Against any other base, a suite it would charge to the task reads not comparable (`not-knowable`), a kept base answers no such red, and the drive measures the base for that red. A red the recorder's writes alone cause then reads as red at base too (`gate-red-base`), and a red the task's work causes beside it is still the task's. The cost is one more base measurement for each red that a kept base would have charged to the task.
