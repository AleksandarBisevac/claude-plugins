- **A stop signal during a red-first proof no longer leaves a run of the command alive.** The signal's exception is raised on the main thread between any two bytecodes, so one landing while the task's run was being started - inside the process start, after the fork, or on its return - left that run held by nothing, in a session of its own, still running after the helper exited. Every run is now started from a thread of its own into a holder the stop reads under a lock, so the stop either cancels the start or waits for it and tears the run down.
