## One correction to the plan's diagnosis

The requirement map records **A2/A3/A4/A9** as *"Root-caused (stale install likely)"*, and the
Context section says the same: *"most likely a report generated by the stale installed plugin"*.

**That hypothesis was wrong, and the real cause is now confirmed by the user: an IDE preview
pane, which sandboxes inline `<script>`.** The page renders completely and looks finished while
every interaction silently does nothing. Established on 2026-08-08 by failing to reproduce it
any other way — Chromium and WebKit, `file://` and `http://`, real mouse and keyboard, five
viewport sizes, hit-testing every control, and the committed example byte-identical to a fresh
render — and then asking.

What this changes for the remaining chunks:

- The **version stamp** (c1, shipped) and the **per-feature JS guards** (c1, shipped) are still
  worth having, but neither would have diagnosed this: the stamp is only visible if you already
  suspect staleness, and the guards protect against one feature killing the others, not against
  no script running at all.
- The **`file://` runtime click-through** in c8 was the right instinct and is the thing that
  would have caught it. It shipped separately, and it also asserts that the new no-script banner
  is *removed* on load — so its absence is live proof the script ran.
- The fix that actually addresses A2/A3/A4/A9 for a reader is the **no-script banner**: rendered
  into the HTML, removed by the script's first statement, visible exactly when it is true. The
  report already had a `<noscript>` for this — the right intent with a mechanism that cannot
  fire, since `<noscript>` renders only when scripting is *disabled* and a preview pane leaves it
  enabled while stripping the inline script.

# Audit Plugin — Report & Panel UI/UX Overhaul + Governance Features

## Context

User's UI/UX review of the plugin's two visual surfaces (generated HTML report, control panel) found dead controls, lost filters, layout jumps, unclear forms, raw labels, and missing capabilities (monorepo scoping, capability policy, audit trail, help). Exploration verified root causes; three design agents produced file-level plans. Goal: flawless, premium, tech-oriented UI/UX (refined Slate & Teal), consistent report+panel, plus four new governance capabilities — all zero-dependency, selftest-gated.

**Key diagnostic finding**: every "dead" report control is statically wired and works in the current renderer. User viewed via file:// — most likely a report generated by the **stale installed plugin** (see memory: marketplace cache vs dev repo). Plan therefore includes: runtime file:// click-through in CI tooling, per-feature JS guards (one failure can't kill everything), and a renderer version stamp in the report footer so stale output is diagnosable at a glance. The *real* verified report bugs: anchors land under sticky topbar (no scroll-margin), sticky z-index collision hiding table headers, `held by` link toggling collapse, 4 inconsistent pill grammars, no model/date filters, filters auto-expanding phases.

**Verified hard panel bugs**: composition writes broken on sharded manifests (patches raw index → "unknown task", discarded phase edits, 22 bogus findings on meta saves); Export report 404 when `meta.reportBasename` set (`panel-server.py:634` passes manifest where meta expected) + popup-blocked `window.open` after `await`; no scrollbar-gutter/routing (nav jumps); no diff-confirm, no journal, no viewer identity, raw `in_progress` labels everywhere.

## User decisions (confirmed)

1. Report was viewed via **file://** → harden + version-stamp + runtime check (above).
2. Palette: **Slate & Teal — refined** (keep identity; unify pills, deepen hierarchy).
3. **All four** new capabilities in scope: capability policy, tamper-evident journal, monorepo areas, help drawer + **audit-guide agent (model: haiku — fast/concise/cheap; fallback sonnet if too shallow)**.

## Answers to the review's open questions (what the plan implements)

- **Monorepo**: new `meta.areas` registry `{tag: {root, description, reviewSkill?, skills?}}`; `/audit:init` detects workspaces (pnpm/yarn workspaces, turbo, nx, lerna, go.work, Cargo, .sln) and proposes registration; resolution `phase.reviewSkill ?? meta.areas[tag].reviewSkill ?? meta.reviewSkill`; executor skills = area defaults + task.skills (deduped, area-first). Free-text `area` stays legal (warn-only).
- **Allow/deny skills/agents/MCP per project & per tag**: yes — `policy` block in audit.config.json + new PreToolUse hook `guard-capabilities.py` (matcher `Skill|Task|Agent|mcp__.*`) with deny/ask/warn modes, "default: deny" master switch + global/per-area allow lists. **Honest limits (documented, not hidden)**: enforced only while plugin enabled; subagent hook inheritance not guaranteed on all versions (doctor warns if hook never fires); Skill-deny blocks the tool not the knowledge; **hooks cannot gate hooks** — other hooks are inventoried in the panel, never enforced.
- **Non-blockable plugin components**: impossible to make unremovable (Claude Code lets users disable plugins — by design). Instead: REQUIRED set (audit's own skills/agents) is enforce-allowed by the hook, panel refuses to write a policy denying them, validate-config flags it, doctor detects it, and the change would be journaled. "Not unremovable — unremovable *quietly*."
- **Can changes evade logging / can logs be edited?** Today yes/yes. After: append-only hash-chained journal (panel writes, CLI, PostToolUse hook for manifest/config edits); `audit-journal.py verify` + doctor detect edits/deletions/reordering + out-of-band drift via stateHash. Tamper-**evident**, not tamper-proof (no secret key possible in stdlib-on-user-machine; deletion is itself loud evidence).
- **Settings page**: yes — Guards tab becomes grouped **Settings** (Paths & gate / Write guards / TDD / Usage & pricing), covering the whole config incl. currently-uneditable `usage.*` and `tddReminder.*`.
- **Current user in panel**: yes — `usage_ledger.resolve_author()` → topbar "viewing as X" + "my spend" filter + journal author.
- **Help**: static-first (zero tokens): `/api/help` serves schema descriptions + concept topics → in-panel "what is this?" drawer; plus `agents/audit-guide.md` (read-only tools, model haiku) for conversational Q&A, explicitly invoked.
